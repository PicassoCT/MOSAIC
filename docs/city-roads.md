# City roads and plot addresses

City roads is enabled by default in the widget selector. It draws terrain-following road strips with alpha **0.5** and street labels with screen-space collision checks. Geometry is cached; the widget reads public rules parameters on revision changes and frees its display list on shutdown. The overlay is cosmetic: it does not change terrain, building orientation, blocking or pathfinding.

Two generation paths share `scripts/lib_city_roads.lua`:

- **Generated by game:** infer the lanes reserved by the existing inner-city grid, at `(2*n + 0.5) * (building size + alley size)`. Width comes from the configured alley width. Cultural names and road IDs are stable. These are logical grid lanes, not a survey of a manually authored map's roads.
- **Generated by map:** load `mosaic/roads.lua` from the map archive. CityLights exports projected, clipped OSM highway polylines and preserves names. Touching ways with the same name share a street ID; disconnected streets with equal names remain distinct.

The map contract is a data-only Lua table:

```lua
return {schema=1, generation="map", roads={
  {id="way/123/1", name="Market Street", width=32,
   points={{400,600},{1200,600},{1800,900}}}
}}
```

All coordinates are Spring world X/Z units. IDs must be unique, widths are 1–128 units, and coordinates are rounded to integer units. Limits are 4096 road pieces and 65536 points. The exported widths are class-based display estimates, not surveyed physical widths. Street names retain UTF-8, with control characters removed.

Each house belongs to the original **plot**, keyed by rounded world X/Z, rather than a unit ID. The initial set is sorted along its street; opposite sides receive odd/even numbers. Imported `addr:street` and `addr:housenumber` take precedence. Generated numbers skip imported numbers. An imported street without matching geometry remains an address-only street instead of being renamed.

The synced service publishes `city_plot_key`, `city_plot_x`, `city_plot_z`, `city_street_id`, `city_street_name`, `city_house_number`, `city_number_source`, and `city_generation` as public unit rules parameters. The tooltip includes the same street and number. Repeated calls and destroyed-house replacements retain the plot's address. A genuinely new plot after initial city completion gets a coordinate suffix, so it cannot renumber existing houses or collide through construction order. Imported duplicate numbers are retained as source data.

CityLights placements may supply an `address` record with these fields. Map and game service implementations must match. The generated map owns the authoritative road network and initial addresses; MOSAIC manages tooltip integration and rebuilding.

Old address code mixed half-grid and world coordinates, chose some street directions randomly and incremented a counter keyed only by display name. This update removes those dependencies, fixes shop array bounds and double-scaled shop coordinates, makes shop descriptors deterministic, and sorts/falls back safely when choosing truck destination names.

Run `lua5.1 tests/city_roads_test.lua` and `lua5.1 tests/city_arcologies_test.lua`. The first suite forbids RNG use and checks reversed geometry/plot order, connected street IDs, UTF-8, imported numbers, repeated registration, rebuilt houses, rules-state recovery, transparency, label collision checks and GL cleanup. The second checks the existing city and arcology lifecycle. CI executes Lua 5.1 on Linux and Windows via Lupa.

Recoil visual rendering and multiplayer use still require an engine smoke test. In particular, inspect lane alignment in each culture, labels at several zoom levels, map-widget loading, and a destroyed/rebuilt house on both game-generated and CityLights maps.
